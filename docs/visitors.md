# Visitor map

The About page contains a compact native Visitor map disclosure. It uses bundled public-domain Natural Earth outlines, small regional pins, a distinct blue You marker, a legend, zoom controls, and an optional device-position marker. Scrolling over the map zooms toward the pointer; scrolling elsewhere moves the page. Markers keep their screen size while zooming. Hover, keyboard focus, or a tap reveals marker details in a tooltip; Escape or clicking outside dismisses it. The map waits for an in-flight visit record before loading the aggregate, then refreshes while open. A timestamp and explicit location status distinguish real data from failed lookups or privacy settings. Precise browser geolocation is requested only after pressing its button and remains in browser memory. It is never posted to the server.

`visitor-tracking.js` records a visit once per document load. The server deduplicates each validated network address per UTC day using a private HMAC secret. DNT and Global Privacy Control prevent automatic recording and server geolocation. Localhost is never recorded. Cloudflare connecting-address headers are accepted only from platform-verified peers inside the official Cloudflare networks; arbitrary forwarded headers are ignored.

The public map exposes 5-degree country-region buckets and daily unique visit totals over the latest seven UTC days. Region markers show the region and count, never lists of other visitors' addresses. The `currentIp` response field contains only the requesting connection's validated public address; it is displayed privately to that visitor in the summary and You tooltip, and never added to shared aggregates or storage. It remains available when a geography lookup fails. The requester's own approximate network estimate is private/no-store and rounded, with at least 50km declared uncertainty. The map starts at Fit world, offers an explicit Your area control, and preserves manual zoom/pan on refresh. Network lookups use GeoJS server-side with an independent IPWho.is HTTPS fallback for timeouts, invalid responses, and outages. Each provider has a bounded response and a 2.5-second timeout. Successful results are cached for an hour; failed results retry after 15 seconds. Neither provider requires a browser API key. VPNs and proxies can affect accuracy. Missing geography produces no fabricated pin. Visits before the feature was installed cannot be reconstructed.

The local server at `http://127.0.0.1:4173` reads the published `/api/visitors` through a fixed, read-only HTTPS endpoint. This shows the same real recorded visits instead of an empty local database. Local visits never write to the production map. The preview's current network estimate is the local server's outgoing network, usually the same network as the browser; the optional device marker remains available. The bridge forwards DNT/GPC, strips unknown fields, and returns an explicit error when live data cannot be reached. It never forwards caller-supplied addresses or URLs.

Storage uses the named `portfolio-visitors` Firestore database in `us-central1`. Browser clients have no database read/write permissions; only the managed function accesses it. Application documents contain coarse aggregates and short-lived daily HMAC keys, never raw addresses. Infrastructure access logs are managed separately. `visitor_days.expiresAt` has a seven-day TTL and `visitor_seen.expiresAt` has a two-day TTL. Queries exclude expired records immediately even while Firestore's asynchronous deletion is pending.

`npm run setup:visitors` prepares the fixed database, retention policies and stable `VISITOR_HASH_SALT` secret through native authenticated HTTPS. It never prints secret values. Deploy with `firebase deploy --only "firestore,functions,hosting" --project personal-website-7d04c`. The function is `visitorAnalytics`, routed at `/api/visitors`. The existing Gemini chat remains a separate function. Public endpoints have request, aggregate, daily-write and region bounds; these are not a hard billing cap.

Run `npm run test:visitors` for provider-free backend and browser tests. Fixtures are intercepted only inside tests and never seeded in the live database. Inspect the live endpoint after deployment to verify real region storage and deduplication.
